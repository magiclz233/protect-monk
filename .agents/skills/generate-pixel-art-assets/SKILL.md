# 《守护唐僧》国潮角色生图与素材整理

这套流程不绑定固定服务商。目标产物是可直接用于《守护唐僧》的英雄、友军和敌对角色的二维素材、左右方向图、动作序列、换皮图和 GIF。

> 兼容说明：skill 名、目录和环境变量仍保留 `pixel`，但本项目已禁止像素风。英雄、友军和敌人统一使用 Q 版风格锁，不按阵营拆分画风。

本项目视觉标准以 `art-source/references/风格板.png` 和已验收的新版素材为准。

P0 静态资产优先采用单资产单文件，不使用候选母图或精灵图。本 skill 的母图、切帧和 GIF 能力主要用于第二批动作素材。

## 先选生成后端

按以下顺序选择，不要求用户重复配置：

1. **当前宿主已有原生生图工具**：直接使用该工具。工具名称、模型和计费方式以当前宿主为准。
2. **当前宿主已有通用图片 API 工具**：使用用户已经配置好的接口，不写死域名、模型或 Key。默认按 OpenAI 兼容图片协议处理，配置项见 [通用图片 API 适配](references/api-adapter.md)。
3. **两者都没有**：只输出可直接粘贴到目标生图平台的完整提示词和参数，不假装已经生成图片。

不得把服务商地址、私有线路、API Key 或私有任务 ID 写入新产物。需要 API 时只读取当前环境已有配置，不要求用户把 Key 发到对话，不把 Key 写入提示词、文件、命令参数或日志。

## 工作流

### 1. 锁定输入

从用户描述和参考图中提取以下信息。只询问会改变成品的缺失项：

- 角色身份、体型、服装、武器、关键颜色和时代/题材。
- 源图画布或单格尺寸，例如 1024×1024、192×288、256×256。
- 本项目默认只做面向左、面向右两个 3/4 方向；只有用户明确要求时才制作四方向或八方向。
- 动作名称、目标帧数、循环方式、是否为原地动作。
- 背景默认使用纯绿 `#00FF00` 或纯洋红 `#FF00FF` chroma 键；透明只用于本地处理后的成品。
- 参考图用途：只参考风格、只参考身份，还是同时锁定姿势和构图。
- 生成数量、预算和是否允许付费调用。没有明确预算时，不自动批量重试。

已有信息直接沿用。角色大小和动作帧数没有明确值时先停在提示词阶段，不能替用户默认；方向默认使用本项目规定的左、右两个 3/4 方向。

### 2. 写全局风格锁

每次生图都复用同一段风格锁，确保不同批次一致。至少包含：

- 二维扁平国潮 Q 版（Guochao Flat），2.5-3 头身，头部约占身高 35%-38%，身体紧凑匀称，不过胖、无婴儿肥。
- 3/4 竖直站立视角，身体绕竖轴转约 30-45 度；镜头只略高于角色、只略微看到头顶，不做 45 度俯拍、鸟瞰、平躺、贴纸或卡牌头像。
- 2 层 cel shading，无渐变；深色粗轮廓约为主体宽度的 4%-5%；高饱和、高对比。
- 只使用少量云纹、水纹、火焰纹、回纹、莲花或龙鳞，不堆砌写实细节。
- 不混用 3D 渲染、写实、厚涂、像素块、剪纸、皮影、欧美魔幻或日本动画风。
- 固定镜头高度、头身比、武器数量、肢体数量、服装层级。
- 单脚或双脚落地点位于画面高度约 78%，重心在脚点正上方，所有帧脚底基线稳定。
- 背景是单一纯色 chroma 键，平整、无纹理、无渐变、无棋盘格、无投影；绿色主体优先使用洋红 `#FF00FF`，其余优先使用纯绿 `#00FF00`。
- 每个画面格子之间不重叠、不跨格、不镜像冒充不同方向。
- 不生成文字、水印、标签、边框、地面、接触阴影、圆形底座、光环、法阵、额外角色或重复武器。

完整模板见 [提示词配方](references/prompt-recipes.md)。

### 3. 生成角色候选母图

需要多个候选时，优先生成一张等格母图，而不是连续发起多次独立请求：

- 候选数量 N 由用户确认，建议 2、4 或 6。
- 使用严格的等宽等高网格，例如 2 列×3 行。
- 每格只放一个完整角色，脚底留在同一基线，四周保留安全边距。
- 每格的角色设计必须可区分，但共享同一世界观、比例和色板。
- 不得出现半身、被裁切、跨格、重复角色或额外装饰。

生成后先检查网格数量、单格尺寸和完整性，再给用户编号选择。不能默认选择第 1 个。

### 4. 生成方向图

本项目默认只生成面向左、面向右两个方向。只有用户明确要求通用方向图时，才确认是否制作四方向或八方向。

首选 3×3 方向母图：

```text
后左 | 后   | 后右
左   | 原图 | 右
前左 | 前   | 前右
```

四方向只使用上、下、左、右四个正方向，不把中心原图算作方向。八方向使用外围八格。

方向图必须保持同一角色身份、同一服装、同一武器、同一比例和同一脚底基线。不能均匀复制同一个正面图充数，也不能用镜像伪装左右方向；左右轮廓、持物手和朝向必须真实不同。

如果宿主支持图生视频，也可以先生成原地转身视频，再逐帧检查并选出实际朝向。不能仅按帧序号猜测方向。

### 5. 分方向生成动作

每个方向使用该方向已经核准的方向图作为参考，分别生成动作。本项目只制作左右两个 3/4 方向，不要把多个方向一次性混在同一张动作母图里。

图片型生图默认输出等格序列图：

- 列数和帧数必须固定，例如 6 列×6 行=36 帧。
- 每格画布等宽等高，角色中心和脚底基线固定。
- 每格按 1:1 正方形画布生成；原图放不下时用所选背景色居中补边，不拉伸、不裁切。画布边长按实际平台限制取整，默认取 32 的倍数。
- 第一帧和最后一帧只在实际需要循环时衔接；非循环动作不强行闭合。
- 攻击、受击等动作保持武器数量、肢体数量和特效层数一致。
- 角色放大、技能光效或武器前伸不能导致身体越格。

生成后用本地工具切帧、检查并合成 GIF。宿主支持视频生成时，可改为逐方向生成视频并抽取关键帧，但最终仍要按实际朝向逐方向验收。

战斗动作的帧数、阶段和提示词见 [战斗素材规范](references/combat-asset-pack.md)。一个方向只做一个动作；攻击、受击、死亡和技能不能混在同一张母图里。

### 6. 换皮和重绘

换皮必须保留原序列的：

- 帧数、行列、单帧尺寸和帧序。
- 身体姿态、动作幅度、镜头和朝向。
- 武器与四肢数量，除非用户明确要求改变。

只替换用户指定的外观元素。输入序列图直接作为图生图参考，不重新自由设计动作。

## API 通用规则

- 默认协议：OpenAI 兼容图片接口。
- 配置来源：用户已有的环境变量、宿主连接器或本地配置文件。
- 环境变量建议：`PIXEL_IMAGE_API_BASE_URL`、`PIXEL_IMAGE_API_KEY`、`PIXEL_IMAGE_MODEL`、`PIXEL_IMAGE_API_PROTOCOL`。
- 文生图使用 `${BASE_URL}/images/generations`；图生图使用 `${BASE_URL}/images/edits`。
- 返回值可以是 `b64_json` 或可下载 URL；保存前校验 MIME、像素尺寸和文件完整性。
- 模型是否支持透明背景、图生图、多图和尺寸参数，以实际接口能力为准；不支持时改用纯色键色背景，再本地抠图。
- 非 OpenAI 兼容服务使用它自己的宿主工具或适配器，不能把同一套请求体硬套上去。
- 付费调用前先确认数量、模型和预算。失败后不自动切换更贵模型，不重复提交状态不确定的任务。

详细请求与配置规则见 [通用图片 API 适配](references/api-adapter.md)。

## 本地处理

需要 Pillow 3.0+。脚本只处理本地文件，不访问网络。

切分规则网格并导出逐帧 PNG：

```sh
python scripts/sprite_tools.py crop-grid --input direction-sheet.png --columns 3 --rows 3 --out directions
```

检查空格、重复帧、脚底漂移、水平中心漂移和非正方形单格：

```sh
python scripts/sprite_tools.py audit --input attack-right-01.png --columns 6 --rows 4 --background 00FF00 --out audit.json
```

把分开生成的多个动作段按顺序拼成完整序列：

```sh
python scripts/sprite_tools.py concat --inputs attack-01.png attack-02.png attack-03.png --input-columns 4 --input-rows 2 --out-columns 6 --background 00FF00 --out attack-right-full
```

从序列图或 GIF 提取帧、抠色并生成 GIF：

```sh
python scripts/sprite_tools.py process --input action-sheet.png --columns 6 --frames 36 --background 00FF00 --tolerance 24 --fps 24 --out action-clean
```

把已有 PNG 帧合成 GIF：

```sh
python scripts/sprite_tools.py gif --input-dir frames --fps 12 --out animation.gif
```

脚本自带最小自检：

```sh
python scripts/sprite_tools.py self-test
```

扁平国潮素材不要为了缩小体积使用 `--colors` 减色，也不要用 `--scale` 做最近邻放大；这些操作会破坏 2 层 cel shading 和抗锯齿边缘。GIF 只作为预览。P0 静态单资产最终处理继续使用 `pnpm assets:prepare`。

## 验收

交付前逐项核对：

- 实际图片尺寸、行列数和帧数。
- 每格只有一个完整角色，没有跨格或裁切。
- 角色身份、服装、武器和身体部件数量前后一致。
- 角色是扁平国潮 Q 版，2.5-3 头身，2 层 cel shading，无渐变和像素块。
- 角色 3/4 竖直站立，不是俯拍、平躺或卡牌头像。
- 目标是右向时角色确实向右，目标是左向时确实向左，不能只镜像补数。
- 攻击方向与角色朝向一致，武器没有中途变成两把或凭空消失。
- 受击没有误画成死亡，死亡最终姿态保持稳定且不是瞬间消失。
- 技能特效没有遮挡角色轮廓或改变身体比例。
- `audit` 报告的空格、重复帧和漂移已经人工复核；死亡停留等有意重复帧要明确记录。
- 动作脚底落点稳定；当前 Phaser 3 项目使用 `setOrigin(0.5, 0.78)`，未来迁移 Godot 时继续沿用 78% 脚点。
- 透明边缘不带明显白边或键色残留。
- GIF 帧序、时长和循环点正确。
- 保留原始母图和未处理序列，不能只交付压缩后的 GIF。

只在文件确实生成并可打开后报告成功。仅提交任务、拿到任务 ID 或显示“处理中”都不算完成。
