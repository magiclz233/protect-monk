### 0.3 四条硬规则

1. **一次只生成一个资产。** 不生成 2×3、2×2、横向多角色、多图标 sheet 或 sprite sheet。
2. **角色必须竖直站立的 3/4 视角。** 45 度只表示绕身体竖轴转身，不表示镜头从头顶 45 度俯拍。
3. **Gemini 不负责真透明和精确像素。** 先生成 1024×1024 单主体图，背景使用纯色 chroma 键；抠图、缩放、脚点对齐和验收由本地完成。
4. **当前代码 key 决定文件名。** P0 使用中文文件名，不使用 `hero_*`、`enemy_*`、`soldier_*`。

## 1. 为什么升级到 v2

v1 的实际问题不是“画得不够细”，而是生产单位错误：

- 旧提示词一边声明多格母图废弃，一边仍要求 2×3 或 2×2 母图。
- 旧法宝图出现系统性切图错误：12 张 PNG 的有效内容边界全部只有 `32×128`，实际是横向 sheet 的竖条切片。
- 多个英雄和敌人图片带有卡牌框、灰白棋盘格或近满画布的不透明背景。
- 旧背景图包含顶部装饰弧线和底部 UI 卡槽，不是纯场景图。
- 固定 `3-4px` 轮廓缩小到 96×96 后只剩不到半像素，轮廓会消失。

v2 统一改为：单资产、短 brief、固定构图块、纯色 chroma 背景、本地抠图和统一验收。

## 4. 统一美术规范

### 4.1 风格

统一采用扁平国潮 Q 版（Guochao Flat）：

- 2.5-3 头身，头部约占身高 35%-38%，身体紧凑匀称，不过胖、无婴儿肥。
- 扁平或硬边块面感，2 层 cel shading，不使用渐变、写实厚涂和 3D 渲染。
- 深色轮廓宽度按主体比例计算，不使用固定 3-4px。
- 高饱和、高对比；只使用少量云纹、水纹、火焰纹、回纹、莲花、龙鳞或骨纹。
- 不使用像素风、剪纸、皮影、欧美魔幻和日本动画风。

### 4.2 棋盘与角色视角

棋盘是俯视正交矩形网格，角色是竖直站立的 3/4 立牌，两者不要求采用同一个相机俯角。

- 角色绕身体竖轴转约 30-45 度。
- 脸、胸腹、腿和身体侧面清楚可见。
- 镜头只轻微高于角色，只能略微看到头顶。
- 不画 45 度俯拍、鸟瞰、平躺、贴纸或卡牌头像。
- 双脚或接地点位于画布高度约 78%，重心在脚点正上方。
- 角色 PNG 内不烘焙接触阴影、圆形底座、光环、法阵或棋盘；落地阴影由游戏引擎按脚点单独绘制。

左右方向是第二批所有角色形态的固定交付维度。P1-B 和 P1-C 也必须在首次生成时同时产出 `right`、`left`，不能只做中立图后再返工。具体提示词见 [Gemini-第二批提示词包.md](./Gemini-第二批提示词包.md)。

## 8. Gemini 生产流程

### 8.1 正确流程

```text
选择资产
  → 拼接固定画风和角色 brief
  → 第一张不上传参考图；之后通常只上传 1 张已验收新图，最多 2 张
  → 生成一张 1024×1024 单主体图
  → 人工检查主体和武器数量
  → 下载原图
  → `pnpm assets:prepare` 自动抠色、裁边、缩放和脚点对齐
  → 放入 art-source/cleaned/
  → 真实棋盘和真实 UI 截图验收
  → 通过后复制到 public/assets/
  → 更新进度表
```

### 8.2 错误流程

```text
一次生成整套角色
一次生成 2×3 或 2×2 母图
一次同时要 right + left
一次生成多角色 sheet 后自动切图
直接要求 Gemini 输出真 alpha 和精确像素
把未验收旧图当风格参考
把孙悟空等既有角色当“角色参考”生成另一个角色
```

### 8.3 Gemini 生成后的本地处理

每张图至少做：

1. 检查主体、手、腿、尾巴、角、翅膀、武器和法宝数量。
2. 用纯色 chroma 背景抠图，得到真 alpha PNG。
3. 去除模型生成的边框、文字、卡牌和背景杂物。
4. 统一主体高度和占格比例，不拉伸角色。
5. 把脚点对齐到画布高度约 78%。
6. 缩放到目标尺寸，检查 64、80、96 和 128 的可读性。
7. 在真实棋盘或真实 UI 中截图验收。
8. 把原图、清理图和退回记录保存在 `art-source/`。

## 9. 验收

### 9.1 单张素材

- 只有一个主体。
- 文件尺寸和命名正确。
- 透明素材是真 alpha，没有白底、绿边、洋红边和灰白棋盘格。
- 角色竖直站立，脚点约 78%，不是俯拍、平躺或卡牌头像。
- 主体高度和占格比例在当前类别内一致。
- 轮廓和主色在目标尺寸下清楚。
- 没有重复武器、额外手脚、额外尾巴、额外眼睛或多个主体。

### 9.2 棋盘合成

- 脚点落在格子中心附近，不悬浮、不压住格线。
- 角色不遮挡关键 UI，攻击方向可辨。
- 引擎添加的接触阴影平贴脚点，不形成圆形底座。
- 缩小后仍能区分角色类型和阵营。

### 9.3 背景

- 750×1334 或等价竖版比例。
- 纯场景，没有 UI、卡槽、按钮、文字、棋盘和路径线。
- 中央区域低对比，棋盘和角色叠加后仍清楚。

> 已确认例外：`战斗背景_森林.png` 保留山峰封条上的小面积环境题字，经用户确认可接受。后续章节背景仍默认无文字，除非另行确认。

### 9.4 状态

建议使用以下状态记录：

```text
missing
draft
review
accepted
rejected
```

只有 `accepted` 可以计入 P0 完成；未验收旧图仅可作为运行占位保留在 `public/assets/`，不得标记为 `accepted`。
