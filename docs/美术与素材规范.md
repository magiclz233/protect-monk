# 《守护唐僧》美术与素材规范

> 现行规范：2026-11-03。本文统一旧配色、素材总纲和九章素材对接的规格；详细生产提示词与原批次记录继续保留，见[素材生产手册](./素材生产手册.md)。
> 文件处理与实际画面验收分开记录，完成状态只维护在[开发与验收计划](./开发与验收计划.md)。可复制模板见[素材生产手册](./素材生产手册.md)。

## 1. 视觉方向

角色使用扁平国潮 Q 版，界面使用「取经绘卷」：宣纸承载内容，墨松绿承载操作，朱砂强调主按钮，鎏金表示奖励和高价值。保留现有界面交互与布局骨架，按实际画面完善一致性。

角色、棋盘、背景和 UI 各有职责：角色轮廓清楚；路径和开放格一眼可辨；背景中央低对比；按钮与文字易读。UI 可以使用现有渐变、阴影和程序绘制，角色生图采用硬边色块。无需把所有面板改成 PNG。

## 3. 角色风格与构图

- 2.5–3 头身，头部约占身高 35%–38%；身体紧凑，保持角色身份和小尺寸轮廓。
- 采用扁平硬边块面、两层明暗，高饱和，深色粗轮廓约为主体宽度的 4%–5%；不用固定几像素描述源图轮廓。
- 新角色不使用写实厚涂、3D、像素风、剪纸或皮影风。少量云纹、火纹、水纹、莲花和骨纹足够，避免缩小后变成噪点。
- 棋盘为俯视正交矩形；角色为竖直站立的 3/4 立牌，绕身体竖轴转约 30–45 度，镜头只略高于角色。
- 不画鸟瞰、平躺贴纸、卡牌头像；头顶、武器、衣摆、尾巴和双脚完整。
- 脚点约为画布高度 78%，重心在脚点上方；Phaser 图片与后续动画使用 `setOrigin(0.5, 0.78)` 或等效偏移。
- 角色图不烘焙棋盘、地面、接触阴影、底座、法阵和 UI；落地阴影与战斗光环由引擎绘制。
- 武器、手脚、翅膀、眼睛、宠物数量按已确认角色参考锁定。方向和动作不能改变装备数量。

角色和特效仍可使用鎏金 `#f0c15a`、朱砂 `#c43d30`、绛红 `#8b1a1a`、翠绿 `#5bc48a`、玉绿 `#2ea07a`、暖灰 `#c4bbb0`、赭石 `#8b5a3c`、宣纸亮面 `#fff1c9`。这是角色色板，不替代 UI 令牌。

兵阶识别为白、绿、蓝、紫、橙，结合边框与装饰层；阵营识别结合师徒暖金红、仙佛青白金、妖王紫绛暗色，不能把配色做成硬性身份替换。

## 5. 目录、键与命名

运行时资源位于 `public/assets/`：`soldiers/`、`heroes/`、`enemies/`、`items/`、`artifacts/`、`ui/`、`effects/`、`audio/`。后续章节素材可使用 `chapters/`，新增目录必须同步加载清单。

生产文件放 `art-source/`：`generated/` 保存原图，`cleaned/` 保存处理中间图，`references/` 保存已确认参考，`previews/` 保存验收预览，`rejected/` 保存退回结果。不要将未处理原图或退回图放入运行时目录。

## 7. 静态图与动画生产规则

1. 新静态图一次一个资产、一个方向、一个形态。先锁定已验收图的身份，再生成方向和动作。
2. 常规源图建议 1024×1024，背景用纯绿或纯洋红，避开主体主色；若工具能可靠输出透明，可直接使用透明图，但仍需检查透明通道和边缘。
3. 精确尺寸、抠图、清边和脚点由本地完成。保留原图，不能仅把带棋盘格的 JPG 改成 PNG 扩展名。
4. 左右必须成对验收。不直接镜像不对称武器、装备、发饰与披风。
5. 动作优先用已验收静态图生成固定机位的视频，按相同动作阶段抽帧，再本地对齐与拼接；不把未经检查的多格角色母图直接切成正式素材。
6. 特效允许一个效果的等格序列；中心、尺度、每帧尺寸固定，不含角色。已安装的素材技能可作为执行工具，最终产物必须满足本规范。
7. 音频先交付短小的单动作音效与可循环无人声 BGM；优先 OGG，最终格式必须经过目标 Android/iOS 微信运行环境验证，必要时提供兼容格式。

## 8. 验收与接入

| 阶段 | 必须提供的证据 |
| --- | --- |
| 原图候选 | 身份正确、武器与肢体数量正确、主体完整 |
| 本地处理 | 尺寸、真实透明通道、无色键残留、脚点与内容边界 |
| 代码接入 | 唯一键、存在的文件路径、实际消费者与缺图回退 |
| 画面验收 | 真实界面/棋盘截图、实际显示尺寸、血条与格子无遮挡 |
| 动画验收 | 左右两组、动作连贯、无漂移变形、循环与结束状态正确 |
| 平台验收 | 资源加载、音频、内存、包体和目标设备表现 |

同时检查 80/96/128 像素原尺寸和放大边缘。技术指标合格不能替代实际画面可用。截图与测量记录统一放入 `art-source/previews/`，按资源名记录，只有画面验收通过才标为最终通过。

优先补齐 HeroSelectView、SummonPanel、InventoryBarView 等现有 PNG 的消费者。`VisualPainter` 和程序化特效先保留为明确回退；无需为了清理占位而删除仍有价值的绘制能力。
