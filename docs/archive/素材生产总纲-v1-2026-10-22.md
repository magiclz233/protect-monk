## 0. 一页结论

### 0.1 现在到底要做什么

**P0 只做“当前游戏能直接使用的静态素材”**，不先做左右方向、动画、升级形态和章节全套背景。

当前运行时静态清单是 **108 个文件**：

| 类别 | 数量 |
| --- | ---: |
| 小兵静态 | 20 |
| 英雄 `1阶` 静态 | 14 |
| 英雄碎片 | 14 |
| 唐僧静态 | 1 |
| 普通敌人 | 10 |
| 精英敌人 | 9 |
| BOSS | 9 |
| 道具图标 | 5 |
| 法宝图标 | 12 |
| 当前 UI / 背景 / 锁格 | 14 |
| **合计** | **108** |

另有 **1 张风格板**作为生产闸门，不计入 108 个运行时文件。

### 0.2 当前资产状态

- `public/assets/` 现有 **95 张非占位图片**。
- 其中 **21 张**可作为现有金标准参考：20 张四类小兵 + 1 张唐僧。
- 其余 **74 张**属于“已有文件但未完成验收”，不能因为文件存在就标记为完成。
- 108 个运行时静态文件中，**7 个英雄 `1阶` 和 9 个敌人当前缺图**，共 **16 个缺口**。
- P0 的实际生产量应按“补齐 16 个缺口 + 重做/验收 71 个未验收文件 + 审计 21 张金标准”计算。

### 0.3 两个批次的边界

| 批次 | 目标 | 包含 | 不包含 |
| --- | --- | --- | --- |
| **P0** | 先让当前游戏有一套统一、可用、能通过小尺寸验收的静态图 | 108 个运行时静态资源 + 1 张风格板 | 左右方向、动画、升级形态、章节全套背景、音效 |
| **第二批** | 在 P0 风格锁定后提升表现力 | 左右方向、升级形态、BOSS 二阶段、动画、章节背景与锁格、UI 皮肤、特效、音效 / BGM | 无 |

### 0.4 三条硬规则

1. **一次只生成一个资产。** 不再让 Gemini 一次生成 2×3、2×2 或多角色母图。
2. **角色必须是竖直站立的 3/4 视角。** “45 度”只允许表示角色绕竖轴转身，不允许表示镜头从头顶 45 度俯拍。
3. **文件名必须以 `AssetKeys.ts` 当前 key 为准。** 不使用旧的英文 `hero_*`、`enemy_*`、`soldier_*` 文件名。

## 1. 文档权威关系

### 1.1 唯一生产入口

以后制作素材时，只把以下文件作为 Gemini 的知识文件：

```text
docs/素材生产总纲.md
docs/游戏配色体系设计文档.md
```

需要角色独有的外观文字时，再额外上传：


上传角色 brief 时必须在对话中注明：

### 1.3 本总纲已经裁决的冲突

| 旧说法 | 最终规则 |
| --- | --- |
| “45 度俯视棋盘视角” | 棋盘是俯视正交网格；角色是竖直站立的 3/4 立牌。镜头只有轻微高位，不是 45 度俯拍 |
| “一次生成 2×3 / 2×2 多格母图” | 一次生成一个资产；需要变体时拆成多次生成 |
| `stage_2 / stage_3 / stage_4` | 统一为 `stage_1 / stage_2 / stage_3` 三种视觉形态；普通英雄只有 `stage_1 / stage_2` |

| 背景可以带底部卡槽 / UI | 战斗背景必须是纯场景图，不画卡槽、按钮、文字、边框或任何 UI |

## 3. 统一美术规范

### 3.1 风格定义

风格名称：**扁平国潮 Q 版（Guochao Flat）**

核心视觉：

- 扁平矢量感；
- 2 层 cel shading，亮面 + 一档暗面；
- 3-4px 有效粗轮廓；
- 高饱和、高对比，优先保证 64×64、80×80、96×96 小尺寸可读；
- Q 版 2.5-3 头身，头部约占身高 35%-38%；
- 身材紧凑匀称，不婴儿肥、不圆胖；
- 云纹、水纹、火焰纹、回纹、莲花、龙鳞只做少量点缀；
- 不模仿具体影视、动画、游戏或版权角色。

禁止：

- 写实、3D、厚涂、油画；
- 渐变、复杂纹理、过多高光；
- 像素风、剪纸、皮影；
- 欧美魔幻、日本动画风；
- 角色卡牌化、贴纸化、头像化；
- 画入棋盘、地面场景、文字、编号、Logo、水印或边框。

### 3.3 棋盘的“混合投影”

这是本项目最重要的视角规则：

- **棋盘**：屏幕正对的俯视正交矩形网格。
- **角色**：像立牌一样站在棋格上，身体主轴接近屏幕竖直。
- **镜头**：只在角色上方略微偏高，能轻微看到头顶和肩部；脸、胸口、腹部、腿仍清楚可见。
- **转身**：角色绕身体竖轴转约 45 度，形成正面偏侧的 3/4 视图。

禁止把“45 度”理解为从头顶向下拍。以下构图直接返工：

- 只看到头顶和肩膀；
- 身体沿棋盘平面压扁；
- 头大脚小；
- 角色像卡片平铺在格子上；
- 脚点被身体或衣摆遮住；
- 角色整体像一个圆形图标。

### 3.4 脚点、阴影和比例

角色类素材统一要求：

1. 双脚、蹄、爪或坐骑接地点位于画布高度约 **78%**，允许 `76%-82%`。
2. 主体重心位于脚点正上方。
3. 脚点以下只保留少量透明留白和接触阴影。
4. 脚下为短宽、半透明、扁平的椭圆接触阴影。
5. 阴影宽度不超过角色主体宽度的 55%，不能画成圆形底座、光环、法阵或棋盘格。
6. 角色主体占格宽约 55%-72%，高度可以超过单格，但脚点必须稳定。

图标类素材不适用脚点规则，主体应居中，保留约 8%-12% 的安全边距。

> 当前 Phaser 代码还没有统一 `setOrigin(0.5, 0.78)`。P0 正式接入前必须完成这一项，否则 78% 脚点素材会显示为悬浮或偏下。

### 3.5 透明背景和生成方式

- 角色、敌人、碎片、道具、法宝、UI 图标：目标为 RGBA PNG，真 alpha 透明。
- 战斗背景和章节背景：不透明，不需要 alpha。
- Gemini 不保证真透明、精确像素或多帧一致性；透明背景、缩放、抠图和尺寸归一化由本地后期完成。
- 如果生成结果是白底或棋盘格，使用纯绿色 `#00ff00` 或洋红 `#ff00ff` 作为临时背景，再抠图；不要直接把灰白棋盘格当透明。
- 不要要求 Gemini 直接输出精确 64×64、80×80、96×96、128×128。先生成高分辨率单张，再本地缩放和裁切。
- 主角色素材使用 PNG 或 WebP；SVG 只用于 UI 图标、简单符号和特效，不作为角色主图路线。

## 4. 目录、文件名和命名规则

### 4.1 运行时目录

```text
public/assets/soldiers/    小兵静态图
public/assets/heroes/      英雄静态图、碎片、唐僧
public/assets/enemies/     普通 / 精英 / BOSS 静态图
public/assets/items/       道具图标
public/assets/artifacts/   法宝图标
public/assets/ui/          当前 UI 图标、背景、锁格
public/assets/effects/     第二批特效
public/assets/audio/       第二批音效和 BGM
public/assets/chapters/    第二批章节背景与锁格
```

建议另建不进入包体的源文件目录：

```text
art-source/
  references/              风格板、棋盘截图、已验收参考图
  generated/               Gemini 原图
  cleaned/                 抠图、缩放、对齐后的中间文件
  rejected/                退回的生成结果
```

`art-source/` 只用于生产管理，不是游戏运行时目录；不要把未验收原图放进 `public/assets/`。

### 4.2 P0 文件名

P0 使用当前代码的 key，不带方向后缀：

```text

英雄：public/assets/heroes/{中文名}_1阶.png
碎片：public/assets/heroes/碎片_{中文名}.png

道具：public/assets/items/{中文名}.png
法宝：public/assets/artifacts/{中文名}.png
UI：public/assets/ui/{中文名}.png
```

示例：

```text
public/assets/soldiers/灵猴兵_3阶.png
public/assets/heroes/孙悟空_1阶.png
```

### 4.3 第二批命名

P0 通过后，方向、动作和升级形态统一使用以下格式：

```text
静态方向：{中文名}_{阶数}阶_stand_right.png
          {中文名}_{阶数}阶_stand_left.png

动作 sheet：{中文名}_{动作}_{方向}.png
动作帧：   {中文名}_{动作}_{方向}_{两位帧号}.png

普通英雄升级：{中文名}_2阶.png
核心英雄升级：{中文名}_2阶.png / {中文名}_3阶.png
BOSS 二阶段：{中文名}_phase_2.png
```

方向只允许 `right` / `left`；帧号只允许两位数字 `01`、`02`、`03`。

以下旧命名不再使用：

```text
hero_sunwukong_stage_1.png
soldier_monkey_rank_1.png
孙悟空_stage_1_stand_right.png
孙悟空_stage_1.png
```

## 8. Gemini 生产流程

### 8.1 Gem 知识文件

推荐只建立两个用途：

| Gem / 会话 | 上传文件 | 用途 |
| --- | --- | --- |
| P0 静态素材 Gem | `素材生产总纲.md` + `游戏配色体系设计文档.md` + 当前角色 brief | 单张静态素材生成 |
| 后处理 / 验收会话 | `素材生产总纲.md` + 棋盘截图 | 判断脚点、透明度、方向和尺寸 |

不要上传：

- `待办清单-素材与上线.md`：它是进度表，不是生成规范；
- 旧 `AI美术音效资源生成清单-完整版.md`：它含 45 度俯视和多格母图；
- 任何未验收的旧 PNG 作为“风格参考”。

### 8.2 参考图分组

每次发送参考图时，在消息里标明用途：

```text
【角色参考】只用于锁定当前角色的脸、服装、武器和主色。
【风格参考】只用于锁定线条、明暗、Q 版比例和小尺寸可读性。
【棋盘参考】只用于判断脚点、格子和站立关系，不得把棋盘画进最终素材。
```

建议的风格参考：

- `唐僧.png`
- `灵猴兵_3阶.png`
- `天兵甲士_3阶.png`
- `妖王骑_3阶.png`
- `道法弓手_3阶.png`

每次只上传 2-4 张。上传太多会让 Gemini 把旧图的问题一起学走。

### 8.3 一次只做一张

正确流程：

```text
选择角色
  → 选择阶段（P0 固定 stage_1）
  → 选择一个方向（P0 固定正面偏侧中立视图）
  → 生成一张 1024×1024 单主体图
  → 人工验收
  → 本地抠图
  → 缩放到目标尺寸
  → 放入 public/assets/
  → 更新清单和验收记录
```

错误流程：

```text
一次生成 7 个英雄
一次生成 6 格 / 4 格母图
一次同时要 right + left
一次生成 20 个小兵 sheet
```

错误流程会产生角色数量错、武器重复、格子串味、尺寸不可控和无法逐张验收的问题。

### 8.4 Gemini 生成后的本地处理

每张图至少做以下处理：

1. 检查主体数量、手、腿、尾巴、翅膀、武器和法宝数量。
2. 删除背景，得到真 alpha PNG。
3. 统一脚点到画布 78% 位置。
4. 统一角色占格比例，不拉伸角色。
5. 将画布缩放到目标尺寸。
6. 检查边缘没有白边、绿边、灰白棋盘格或残留阴影。
7. 用最终文件名保存到正确目录。
8. 在 `art-source/` 保留原图和清理记录。

## 9. 可复制的单资产提示词

### 9.1 角色 / 英雄 / 敌人通用模板

```text
你在为《守护唐僧》Q 版西游合成塔防游戏生成一张可商用的独立静态游戏素材。

【本次只生成一个资产】
角色名称：{角色名}
角色类型：{小兵 / 英雄 / 普通敌人 / 精英敌人 / BOSS}
视觉阶段：{stage_1 / stage_2 / stage_3}
目标最终尺寸：{80×80 / 96×96 / 128×128}

【角色外观】
{从角色 brief 粘贴：角色定位、基础外观、主色、服装、武器、标志物和不改变的身份特征}

【数量锁定】
主体数量：1
头：1
手臂：2
腿：2
武器：{精确数量和种类}
尾巴 / 角 / 翅膀 / 法宝：{精确数量}
禁止复制武器、额外手脚、额外尾巴、额外眼睛、备用武器和武器残影。

【构图】
只出现一个完整角色，单张图片，不要母图，不要多格拼图，不要 sprite sheet。
角色采用正面偏侧的 3/4 站立视图，绕身体竖轴转约 45 度。
身体从脚底向画面正上方竖直站立，脸、胸腹、腿和身体侧面清楚可见。

双脚或接地点位于画布高度约 78%，重心在脚点正上方。

【画风】
扁平国潮 Q 版，2.5-3 头身，头部占身高约 35%-38%。

主色使用项目的鎏金、朱砂、绛红、翠绿、石绿、暖灰、赭石、宣纸、玄青、墨蓝。
中式纹样只做少量云纹、水纹、火焰纹、回纹、莲花或龙鳞点缀。
不要写实、3D、厚涂、像素风、剪纸、皮影、欧美魔幻、日本动画风。
不要模仿任何具体影视、动画、游戏或版权角色。

【输出】
透明背景 PNG 优先；如果工具不能生成真透明，请使用纯绿色 #00ff00 背景，并保证背景没有渐变、纹理、文字和阴影。
画面中不要出现文字、编号、水印、Logo、边框、棋盘、地面、场景或 UI。
不要裁切头饰、武器、尾巴、翅膀、衣摆、双脚和接触阴影。
```

## 10. 验收标准

### 10.1 单张素材验收

- [ ] 文件名与 `AssetKeys.ts` / 本总纲完全一致。
- [ ] 尺寸符合目标，画布比例正确。
- [ ] 透明素材为真 alpha，没有灰白棋盘格、白底或绿边。
- [ ] 主体只有一个，手、腿、尾巴、翅膀、角和武器数量正确。
- [ ] 角色是竖直 3/4 站立，不是头部俯拍或平躺贴纸。
- [ ] 脚点在画布高度约 78%，接触阴影扁平、短宽、半透明。
- [ ] 轮廓在 64/80/96/128 小尺寸下仍然清楚。
- [ ] 主色和阵营色符合项目色板。
- [ ] 没有文字、Logo、水印、边框、棋盘和场景。
- [ ] 没有裁切头饰、武器、尾巴、翅膀、衣摆、脚和阴影。

### 10.2 棋盘合成验收

把每个角色至少放到真实棋盘的以下三个位置预览：

- 棋盘中央；
- 棋盘边缘；
- 相邻两个单位同时存在的格子。

通过标准：

- [ ] 脚点落在格子中心附近。
- [ ] 身体明显从格面向上竖立，不是沿地面铺开。
- [ ] 能看到脸、胸腹和腿部，不是只见头顶。
- [ ] 不遮满整个格子，格面和相邻格边界仍可辨认。
- [ ] 与相邻单位叠加时层级和遮挡关系合理。
- [ ] 小兵、英雄、敌人和唐僧在视觉体量上仍属于同一套美术。

### 10.3 背景验收

- [ ] 750×1334，无 UI 卡槽。
- [ ] 中央有足够空间放置棋盘。
- [ ] 不把棋盘、路径格、按钮、文字或 HUD 画进背景。
- [ ] 叠加棋盘后，路径和单位仍然清楚。
- [ ] 背景颜色不抢角色的主色和描边。

### 10.4 工程验收

- [ ] `pnpm build` 通过。
- [ ] 资源路径大小写和中文文件名可被 Phaser 预加载。
- [ ] 缺图时仍能回退到 `VisualPainter` 或 UI `Graphics`。
- [ ] 新增或替换的资源已登记到 `AssetKeys.ts`。
- [ ] 运行时实际显示的是新素材，而不是旧占位图。
- [ ] 至少完成一次桌面预览和一次目标移动端比例预览。

### 10.5 验收状态建议

每张资产记录以下状态，不能只记录“有没有文件”：

```text
missing       缺图
generated     已生成，未处理
cleaned       已抠图 / 缩放
review        待人工验收
accepted      已验收，可接入
integrated    已接入运行时
rework        退回重做
deprecated    废弃，不再使用
```
