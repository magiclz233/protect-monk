# 《守护唐僧》Gemini P0 单资产提示词包

> 版本：v2.11 | 日期：2026-10-26
>
> 本文件是 P0 静态素材的唯一提示词入口。旧版多格母图、sprite sheet、横向多角色提示词只保留在 `docs/archive/`，不要再作为 Gemini 知识文件上传。

## 1. 使用规则

- 一次只生成一个资产、一个角色、一个阶段、一个中立姿态。
- 第一张 `孙悟空_1阶` 不上传任何旧图；通过验收后，才把它作为后续新角色的唯一画风锚点。
- 生成同一角色时，已验收图标记为`【角色参考】`；生成不同角色时，只能标记为`【风格参考，不是角色设定】`。
- 新角色最多上传 1 张孙悟空作为画风参考。不要继承孙悟空的凤翅冠、紧箍、红披风、虎皮裙和金箍棒。
- P0 生图对话不要上传棋盘截图；棋盘截图只在本地做最终站姿验收，避免 Gemini 把棋盘画进素材。
- 每次生成一张 1024×1024 的方形单主体图，最终尺寸由本地后期处理。
- Gemini 负责主体、轮廓和配色；抠图、缩放、脚点对齐和小尺寸验收由本地完成。
- P0 使用当前运行时 key：英雄和 BOSS 只做 `stage_1` / `phase_1` 对应的中立静态图，不生成左右方向和升级形态。
- Gemini 只上传现行 v2 已验收参考图。`public/assets/` 中另外 20 张小兵、10 个普通敌人和唐僧属于用户确认的旧风格例外，禁止上传，也不得作为新图或风格板参考。
- 每次发送完整提示词后追加一句：`直接生成一张图片，不要解释，不要生成多张，不要输出分镜或拼图。`

## 2. 固定块

### 2.1 角色、英雄、普通敌人、精英、BOSS

```text
只生成一个完整游戏单位，单张图，不要分格、拼图、sprite sheet、卡牌框或场景。
角色全身采用正面偏侧的 3/4 站立视图，身体绕竖轴转约 30-45 度，身体从脚底向画面上方竖直站立，不是俯拍，不是贴纸，不是卡牌头像。
头顶、武器、衣摆、尾巴和脚部必须完整，主体居中；脚底位于画布高度约 78%。
角色图内不要烘焙接触阴影、圆形底座、光环或地面投影；落地阴影由游戏引擎按脚点单独绘制。
画风为扁平国潮 Q 版，2.5-3 头身，2 层 cel shading，无渐变；深色粗轮廓约为角色主体宽度的 4%-5%，高饱和、高对比；缩小到 80×80、96×96 或 128×128 后仍能看清脸、主色、武器和轮廓。
背景为单一纯色 chroma 键，按角色主色选择绿色或洋红色；背景平整、无纹理、无渐变、无投影、无边框。
```

## 6. 本地后处理和验收

每张图按以下顺序处理：

1. 检查主体数量、武器数量、手、腿、尾巴、角、翅膀和眼睛数量。
2. 下载 Gemini 原图后，运行 `pnpm assets:prepare` 自动移除 chroma、清理边缘、裁边、缩放、对齐脚点并校验尺寸和脚点。
3. 移除模型生成的边框、文字、卡牌和背景杂物。
4. 统一角色高度和占格比例，脚点对齐到画布高度约 78%。
5. 缩放到目标尺寸，检查 80×80、96×96、128×128 和 64×64 图标可读性。
6. 用真实棋盘和真实 UI 截图验收，文件存在不算通过。

单张处理命令：

```powershell
pnpm assets:prepare -- "D:\下载\原图.jpg" --type hero --name "孙悟空_1阶" --force
```

`--type` 可用：`soldier`、`hero`、`shard`、`monk`、`enemy`、`elite`、`boss`、`item`、`artifact`、`ui`、`lock`、`background`。脚本会自动输出正式文件到 `public/assets/`，并在 `art-source/cleaned/` 保留清理后的中间图。

通过标准：

- 同一批素材放在一起像同一款游戏。
- 角色竖直站立，脚点稳定，不是卡牌头像或贴纸。
- 最终 PNG 没有可见亮绿边或洋红边；透明边缘已清理。
- 轮廓、主色、武器和朝向在目标尺寸下仍然清楚。
- 背景没有 UI、卡槽、文字、棋盘和边框。
- 没有重复武器、额外手脚、多个主体或错误切图。
