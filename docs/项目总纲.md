# 《守护唐僧》项目总纲

> 文档基线：2026-11-03；核对代码：`master@a12dc1c`。这是当前项目的统一阅读入口。
> 本次整理统一现行规则和进度，不改变游戏实现。后续状态只在《开发与验收计划》中更新。

## 1. 项目定位

《守护唐僧》是竖屏西游合成塔防游戏，核心操作为召唤、上阵、合成、激活英雄和释放法宝。玩家在有限格子与仙桃之间分配资源，阻止妖怪抵达唐僧。

- 守护模式提供随机地图、逐波挑战、无尽冲分和个人段位。
- 八十一难提供九章八十一关、章节机制、英雄与法宝解锁、局外养成和周目。
- 两个模式共用战斗、棋盘、单位、卡池和素材系统。
- 当前采用 Phaser 3、TypeScript、Vite，本地存档；以微信小游戏为发布目标，同时提供浏览器调试和预览。
- 设计参考局长为 3–8 分钟；守护无尽没有固定结束时间，实际节奏仍需试玩验证。

## 3. 现行范围

### 已有实现，继续验收

1. 四类小兵、五阶合成，十四名英雄及碎片激活、经验成长和局外升星。
2. 统一仓库、道具、十二件法宝、三类阵营羁绊和唐僧全图光环。
3. 守护二十波后无尽、九套棋盘、九种精英与九个 BOSS 轮换。
4. 九章八十一关、选将、扫荡、章节解锁、每日祈愿和无尽碎片宝箱。
5. 本地存档、个人排行、广告封装、微信适配层和双格式构建。
6. 「取经绘卷」新版 UI 与 P0 静态资源接入。

以上表示存在代码和界面，不代表全部玩法、视觉或平台已验收通过。

### 当前交付目标

做出能够在目标手机上完整游玩、画面一致、首次操作清楚、进度可靠保存的版本。先校准测试，验证微信运行与包体，完成现有素材和 UI 的验收，再以代表角色跑通动画与基础声音。

### 后续范围

全量双向动作、英雄升级形态、BOSS 第二阶段、九章专属背景与障碍物、扩展音效和 BGM，在生产与运行闭环确认后分批实施。

好友榜、全服榜、云存档、账号和运营活动属于后续产品需求；当前没有确定后端技术选型。碎片置换「3 普通换 1 随机核心」已取消，不进入当前开发计划。

## 4. 冲突取舍

| 历史分歧 | 当前统一结论 |
| --- | --- |
| 核心闭环尚未实现 | 已有较完整实现，工作重点转为验证和交付 |
| 只配置前十八关 | 已配置八十一关；先重点试玩前两章，不删除后续内容 |
| 全项目固定八列六行 | 九章采用各自的行列、路径和初始开放格模板 |
| 选三人、权重三倍 | 最多选四名已解锁英雄，选中碎片基础权重五倍 |
| 抽卡多种道具混池 | 基础概率为小兵 66%、英雄碎片 22%、开山斧 12%；保底会改变实际结果分布 |
| 守护二十波胜利 | 二十波后进入无尽，唐僧归零结算 |
| P0 为 108、109 或 111 项 | P0 为 109 项；首页插画和 `关卡地图背景.png` 另算，当前启动加载共 111 项 |
| UI 重制尚未开始 | 2026-10-30 已有整体换肤，仍需补齐素材消费者并逐页验收 |
| 旧墨蓝面板、剪纸皮影风 | UI 使用取经绘卷的宣纸、墨松绿、朱砂和鎏金；新角色使用扁平国潮 Q 版 |
| 已有 PNG 即完成美术 | 分别记录文件处理、代码接入和画面验收 |
| 多角色、多图标母图持续生产 | 新静态资产一次一个主体；已保留旧素材不重生成，不作为新画风参考 |
| 所有增强素材都是发布前置 | 代表样本先通过实际运行与小尺寸验收，再按价值扩量 |

## 6. 文档维护规则

- 玩法规则只写入《玩法与数值设计》；素材规范只写入《美术与素材规范》；完成状态只写入《开发与验收计划》。手册只提供执行模板。
- 规则调整要同时修改实现、必要检查和对应规则文档。不能为消除测试失败而修改已确认的玩法。
- 代码用于说明当前实现，文档用于说明目标；两者冲突时先登记差异，再决定改代码或改规则，不能默认实现永远正确。
- 完成记录要写明日期、命令或截图依据，明确区分代码完成、测试通过、平台验证和视觉验收。
- 已被替代的开发旧文档和废弃规范由 Git 保留历史；仍可执行、参考或返修的素材生成文档保留在工作目录。后续不再创建重复进度台账，新增具体资产提示词可以作为生产专用文档。
